# Pi Portable

- Personal project; GitHub remote is `JiugeLi/PI_exe`. Switch `gh` to `JiugeLi` before remote operations.
- Ship the original Pi CLI with its dependencies and a bundled Node runtime. Do not substitute a reimplemented agent or silently download runtimes at launch.
- Windows and Linux x86_64 are separate builds. Linux Node requires glibc; do not claim Alpine/musl compatibility.
- Use the launch working directory, never change to the executable directory. Pi data and extracted runtime live in `<cwd>/.pi-portable`; use `PI_CODING_AGENT_DIR` to avoid changing `~/.pi/agent`.
- Preserve original filesystem and command permissions, server HOME, SSH, Git configuration and inherited PATH. Working directory is not a sandbox.
- Public executables and release ZIPs must contain no credentials. Never import a home-directory provider/auth file during builds. Keep artifacts/cache ignored; private configs and legacy credential-bearing binaries belong under ignored `private/` and must never be published.
- Deliver single executables named `pi-windows-x64.exe` and `pi-linux-x64`, without provider branding. Generate `config.json`, `README.zh-CN.md` and `README.en.md` beside the executable only when missing. Keep both user guides bilingual and synchronized.
- `config.json` is reread each launch; `PI_PORTABLE_CONFIG` overrides its location. Nonempty config keys override saved login keys, but empty config keys must preserve native `/login` credentials. Never compile keys into payloads or log JSON parse snippets.
- SoloMux uses a native `Provider` with `envApiKeyAuth`, like DeepSeek; do not fake OAuth or replace `/login` with a custom command. Login discovers models and publishes the prefetched catalog during credential synchronization. Keep cache entries provider-scoped as `solomux`.
- Pi's extension `pi-ai` alias also rewrites subpaths to `compat.js/...`; load native provider API files from the pinned bundled `PI_PACKAGE_DIR/node_modules/.../dist` using absolute file URLs inside an async extension factory. Its import-only exports cannot be resolved with CommonJS `require.resolve`.
- Update the bundled `solomux.ts` on runtime upgrades with a backup outside the active extensions directory; exclusive config seeding must not leave an obsolete provider implementation active.
- Release checks: `node --test tests/config.test.mjs`, `python scripts/test_launcher.py`, `python scripts/audit_release.py`, and `scripts/verify_native.py` on both platforms. Native integration needs a private key outside release inputs.
- Before public GitHub publication, scan all Git history and exact executable payloads for private credentials; never upload ignored private configs, runtime folders or legacy binaries. Keep public release checksums with the assets.
- Verify cold extraction, repeat launch, original version/help, cached model discovery, real model reply and actual file/shell tools. Label Windows and Linux verification separately.
- Launch the upstream CLI as a separate Node entrypoint to preserve its loader behavior. Windows dynamic imports, if needed elsewhere, require `pathToFileURL`.
- Seed cached rg/fd binaries with exclusive creation; do not overwrite them each launch, since Windows locks executables used by concurrent sessions.
- Noninteractive CLI tests over SSH must set stdin to `DEVNULL` (or redirect `</dev/null`): Pi reads piped stdin until EOF before starting a prompt. An open SSH stdin can look like a hung model request.
- Extraction progress belongs on stderr, never stdout (JSON/RPC). Report 100% only after the complete marker and runtime publication succeed; cached launches stay quiet.
- Launcher-only rebuilds may reuse payloads only after validating the prior manifest hash and unchanged runtime/provision sources (`scripts/build.py --launcher-only`).
